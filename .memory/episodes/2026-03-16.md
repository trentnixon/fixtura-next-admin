# Episode — 2026-03-16

## Context

Implementing design changes from `.comms/admin-implementation-guide-2026-03.md` for the Data page (`/dashboard/data`). Scope filter was returning empty for Clients List and Association to Competition tabs; Association Single tab had no data.

## Work Done

- **Types:** Updated `scraperLogs.ts` — JobSummary/LogEntry: `scope` nullable, added `bullJobId`, `attempt`, `cmsReceivedAt`, `cmsProcessingDurationMs`, `payload`; EventCounts: added `failed`; FetchScraperLogsParams: `scope` optional
- **Scope optional:** fetchScraperLogs and useScraperLogs now accept omitted scope for "All scopes"
- **Scope filter fix:** API expects response format (`clients_list`, `association_to_competition`), not queue names (`scrape:clients-list`). Updated fetch, hook, and UI
- **All Scopes tab:** Added as first tab; omits scope param
- **UI:** Jobs table — Scope column, Bull Job column; entry detail modal — CMS (ms), Bull columns; formatScopeLabel for null/display
- **Association Single removed:** API groups association-single jobs under `association_to_competition`; removed empty tab

## Decisions

- Scraper logs scope filter uses API response format (`clients_list`, `association_to_competition`), not queue names
- Association Single jobs are not separately filterable; they appear under Association to Competition

## Results

- All Scopes, Clients List, and Association to Competition tabs show correct filtered data
- New fields (bullJobId, attempt, cmsProcessingDurationMs) surfaced in UI
