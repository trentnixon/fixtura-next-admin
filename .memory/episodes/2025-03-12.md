# Episode — 2025-03-12

## Context

Integrating the CMS scraper logs list endpoint (`GET /api/fixtura-scraper/logs`) into the Data page UI. The endpoint provides job summaries, timeline aggregations, and pagination for both `clients_list` and `association_to_competition` scopes.

## Work Done

- **Phase 1:** Defined TypeScript types in `src/types/scraperLogs.ts`; implemented `fetchScraperLogs` in `src/lib/services/data-collection/`
- **Phase 2:** Created `useScraperLogs` TanStack Query hook in `src/hooks/data-collection/` with scope validation, caching, and polling for in-progress jobs
- **Phase 3:** Built `ScraperLogsSection` with summary cards, jobs table, pagination, date range filter, loading/error/empty states
- **Phase 4:** Added `ScraperLogsCharts` (jobs over time, status distribution, duration over time) using ChartCard/Recharts
- **Phase 5:** Job detail modal with `include=entries` event timeline; scope selector (tabs); refresh button and polling
- Moved trigger buttons into tabs with scope in `ScraperLogsSectionWithScopeSelector`; removed `ClientsListScrapeSection` and `AssociationToCompetitionScrapeSection`

## Decisions

- Use `fixtura-scraper/logs` path (no leading `/api`) — baseURL already includes `/api`
- Poll every 10s when `meta.summary.byStatus.in_progress > 0`
- Track `loadingFor` per scope so only the active trigger shows "Queuing…"

## Results

- TKT-2026-002 completed. Data page now shows a single tabbed section: Clients List and Association to Competition, each with its trigger button and logs/charts.
